# 规格说明：《收纳大师》活动入口中心（Activity Center）

> 版本 v1 · 2026-09-30 · 对应 backlog P1「留存入口 / 活动入口侧栏」
> 触发来源：用户反馈「这种留存性质或者促进活跃的活动，或者促销的东西应该得有个入口显示才对，
> 可以放在游戏的左右两侧，按列放置，可以滑动，里面有很多按钮，点哪个出来哪个」

---

## 1. 背景与问题

当前 Demo 的留存 / 活跃 / 促销功能（签到、每日谜题、分享、排行、商城、首充、月卡、去广告）
**分散且无统一入口**：

| 功能 | 现状 | 问题 |
|---|---|---|
| 每日签到 | 已有完整实现（`signOverlay`） | 仅"启动时自动弹一次"，弹过就再也找不到；用户想主动补领无从下手 |
| 过关说明 | 已有（`helpOverlay`） | 只有 header 一个小「?」，位置弱 |
| 去广告卡 | 已有（footer 按钮） | 埋在底部第二行，促销转化路径长 |
| 每日谜题 / 分享 / 排行 / 商城 / 首充 / 月卡 | 未实现 | 完全没有入口，玩家无感知，后续做完也"没人看得见" |

**核心结论**：休闲游戏的活动曝光靠「常驻入口」而非「一次性弹窗」。缺少常驻入口 →
留存活动触达不到、促销转化率低、已做功能被浪费。

---

## 2. 目标与非目标

### 目标
1. 屏幕**左右两侧**各一根常驻竖向入口栏（列式排布）。
2. 每根栏内可放**多个按钮**，超出可视高度时**可纵向滑动**。
3. **点哪个开哪个**：每个按钮直达它对应的界面（已实现的弹窗 / 未实现的预告弹窗）。
4. 入口**数据驱动**：新增一个活动只加一行配置 + 一处路由，不动布局代码。
5. 不遮挡棋盘、不遮挡底部常驻提示行、不破坏现有四约束与多尺寸自适应。

### 非目标（本轮不做）
- 不实现「每日谜题 / 分享 / 排行 / 商城 / 首充 / 月卡」的具体业务逻辑，本轮只给**入口 + 预告弹窗**（各自在原优先级轮次落地）。
- 不做入口栏的展开/收起动画（记为新增优化项，见 §8）。
- 不引入任何图片 / 字体 / CDN（图标沿用系统 emoji，属于字形而非外部资源）。

---

## 3. 方案设计

### 3.1 交互与视觉
- 位置：`#stage` 内绝对定位，`left:3px` / `right:3px`，垂直居中（`top:50%` + `translateY(-50%)`）。
- 尺寸：栏宽 `42px`，`max-height:66%`；按钮 `42×~46px`（emoji 16px + 9px 文字标签两行）。
- 溢出：`overflow-y:auto` + `touch-action:pan-y` + 隐藏滚动条 → **可上下滑动**。
- 层级：`z-index:10`，低于所有 `.overlay`（`z-index:50`）→ 弹窗期间被遮罩盖住、不可误触。
- 角标：`签到` 待领取时亮红点（`pendingSign`），形成"有东西没领"的拉动。

### 3.2 双栏分工（业务语义）
| 栏位 | 定位 | 当前条目 |
|---|---|---|
| 左栏 `#railL` | 留存 / 活跃 | 签到 📅、每日 🧩、分享 📤、排行 🏆 |
| 右栏 `#railR` | 促销 / 变现 | 商城 🛒、首充 🎁、月卡 💳、去广告 🚫 |

### 3.3 棋盘避让（关键）
`layout()` 的 `marginX` 由 `16` 改为 `16 + RAIL_PAD`（`RAIL_PAD = 48`），
即左右各预留 48px 安全区，保证**管子永远不被入口栏压住**、`tubeRects` 全部落在栏内侧。
底部常驻提示行位于 `H-8` 水平居中，而入口栏只占左右 ~45px 且垂直居中（`66%` 高度），
两端与提示行**几何不相交**。

### 3.4 路由规则（点哪个开哪个）
```
openEntry(id)
 ├─ "sign"  → showSign()                       // 已实现：每日签到弹窗
 ├─ "noads" → btnNoAds.click()                 // 已实现：内购去广告流程
 └─ 其它    → showEntry(id)                    // 通用「功能预告」弹窗（读 ENTRY_META）
```

## 5. 接口

| 名称 | 签名 | 说明 |
|---|---|---|
| `buildRail()` | `() => void` | 启动时按 `RAIL_ITEMS` 渲染两根栏，绑定点击 → `openEntry(id)`，末尾调 `refreshRail()` |
| `refreshRail()` | `() => void` | 刷新角标：`pendingSign` 为真时「签到」红点显示 |
| `openEntry(id)` | `(string) => void` | 入口路由（见 §3.4） |
| `showEntry(id)` | `(string) => void` | 用 `ENTRY_META[id]` 填充 `#entryOverlay` 并显示 |
| `showHelp()` | `() => void` | 抽出（原内联）显示过关说明，供 header「?」复用 |
| `RAIL_PAD` | `let 48` | 左右安全区宽度；置 0 即"不占位"（为后续收起功能预留） |

DOM 新增：`#railL`、`#railR`、`#entryOverlay`（标题含 `#entryIco`/`#entryTitle`，正文 `#entryDesc`，按钮 `#btnEntryClose`）。

## 6. 验收标准

1. **语法**：抽出 `<script>` 过 `node --check` → `SYNTAX_OK`。
2. **渲染回归**：Node 桩在三档尺寸（500×600 / 500×160 / 340×640）下
   `tubeRects.length > 0`、所有矩形在 `W/H` 界内、`arc` 调用数 > 0、常驻提示行未被入口栏覆盖。
3. **入口渲染**：`buildRail()` 后左右栏各 4 个按钮，共 8 个；按钮带 `data-entry` 且 `railBtns` 引用齐备。
4. **路由**：`openEntry("sign")` → `#signOverlay` 为 `flex`；
   `openEntry("daily")` → `#entryOverlay` 为 `flex` 且标题为「每日谜题」；
   `openEntry("noads")` → 触发去广告流程（复用既有按钮）。
5. **角标**：`pendingSign=true` 时 `refreshRail()` 令「签到」红点 `display:block`，领取后 `none`。
6. **不回归**：核心玩法、求解器、评分、存档、签到逻辑与既有单项测试全部保持通过。
7. **四约束**：单文件 `file://` 可运行；零外部资源；中文 UI + 既有 CSS 变量；四约束（单指操作 / 难度递进 / 广告与内购钩子保留 / 无数值售卖）不变。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 入口栏压住棋盘 | 无法点管，玩法报废 | `layout()` 预留 `RAIL_PAD`，验收项 2 断言矩形在界内 |
| 入口栏压住常驻提示 | 首屏说明被挡 | 栏垂直居中且限高 66%，提示行在 `H-8`，几何不相交；验收项 2 校验 |
| 窄屏（≤340）被挤爆 | 管子过小 | `tw` 有 36px 下限、`th` 有 40px 下限；340 宽实测 `startX=76 > 64` 仍有余量 |
| 入口在弹窗期间可点 | 状态串扰 | 入口栏 `z-index:10` < 弹窗 `z-index:50`，被全屏遮罩盖住 |
| 矮屏（160 高）放不下 4 个按钮 | 无法触达 | `overflow-y:auto` 可滑动，本身就是需求 |
| emoji 被视作"外部资源" | 违反铁律 | emoji 为系统字形，非下载资源；且文件既有 🔊/🔇 先例 |

## 8. 后续演进（记为 backlog 新增项）

- **入口栏收起/展开**：极限窄屏或玩家嫌挡时一键收起（`RAIL_PAD` 置 0 + `display:none` + 重新 `layout()`）。
- **入口红点统一化**：`refreshRail` 扩展为读取各活动的"可领/未读"状态，统一驱动红点与数字角标。
- **入口排序按数据**：把 `RAIL_ITEMS` 抽为可配置（运营权重排序、AB 分流）。
- **入口埋点**：`openEntry` 上报 `entry_click`（id、位置、关卡），为 §3.3 的转化分析留数据。
