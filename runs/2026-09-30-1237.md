# 第 97 轮 · 修 2 个用户反馈 Bug + 自查挖出「提示给错步」+ 动画可跳过（P0）

## 一、用户反馈 Bug（优先修）

### Bug1 · 签到领取完成后重进弹窗关不掉
**用户描述**：每日签到领取完成后，点左侧按钮再进去，点按钮无法关闭。

**根因**：`#signOverlay` 里**只有「领取」一个按钮**，`claimSign()` 第一行是 `if(!pendingSign) return;`（领取后 `pendingSign=false`），且该弹窗没有遮罩点击关闭 —— 领取完再进入，唯一按钮直接空转，形成死局。

**修法**（`index.html`，签到区块 L290-327）：
- 抽 `closeSign()` 统一关闭。
- 抽 `syncSignBtn()`：按钮随领取态在 **「领取」(act primary) ↔ 「关闭」(act)** 之间切换；`showSign()` 与 `claimSign()` 结束都调用。
- `claimSign()` 改为：非待领取态 → 直接 `closeSign()`；待领取态 → 发币 + 写 `signClaimedDate` + 关闭 + `refreshRail()` + `toast`。
- 给 `#signOverlay` 补遮罩点击关闭（与 help/entry/share/daily 行为一致）：
  `addEventListener("click", ev => { if(ev.target.id==="signOverlay") closeSign(); })`

### Bug2 · 底部「去广告卡(内购)」与右侧活动栏入口重复
**用户描述**：底部按钮把去广告卡去掉，因为它跟右侧按钮功能重复。

**根因**：底部 `#btnNoAds` 与右侧活动栏「🚫去广告」都走同一段 `showPurchase` 内购流程；但 `openEntry("noads")` 原先写的是 `document.getElementById("btnNoAds").click()`，**直接删 DOM 会抛错**。

**修法**：
- 先把 `btnNoAds.onclick` 的函数体抽成 `function buyNoAds(){...}`（`showPurchase` 回调里置 `noAds=true`）。
- `openEntry("noads")` 改为 `buyNoAds();`。
- 删除底部 `<button id="btnNoAds" …>去广告卡(内购)</button>`，并把该 footer 的 `grid-template-columns:repeat(2,1fr)` 改为 `1fr`（只剩静音按钮）。

## 二、自查挖出的既有 Bug（顺手修了）

### 提示（`btnHint`）给的是「解路径的最后一步」而非首步
**发现路径**：写「动画可跳过」用例时，用 `solve().first` 当首步去驱动一次真实倒球，结果 `canPour()` 为 false；打印后确认 `solve` 返回的 `[i,j]` 对当前局面非法。

**根因**：`solve()` 的 `dfs` 是递归**从最深层往上返回** true 的，而 `if(bestFirst===null) bestFirst=[i,j];` 写在 `dfs(ns,…)` 返回之后 → **最深层先写入**，于是 `bestFirst` 实际是"终局前最后一步"，命名 `first` 与实际语义不符。

**修法**：加深度限定，只记根节点首步
```js
if(dfs(ns, depth+1)){
  if(depth===0 && bestFirst===null) bestFirst=[i,j];   // 只记根节点这一步
  return true;
}
```
影响面：`solve` 的**可解性判定不受影响**（返回真值语义未变），仅 `first` 字段由"最后一步"修正为"首步"；`genDaily` 的可解校验、`btnHint` 的提示高亮同时受益。

## 三、本轮新功能（P0）

### 动画可跳过
- 新增 `skipAnim()`：`anim=null; animating=false; render(); afterMove();`。安全性依据：**逻辑态在 `pour()` 时就已即时更新，动画只负责表现**，所以跳过不丢步、不回滚。
- 新增 `anyModalOpen()`（检查 `winOverlay`/`deadOverlay`/`adOverlay`/`genOverlay` 是否 `display:flex`）：跳过动画的瞬间可能弹出胜负/死局层，此时**中止本次点按透传**，避免误触到被遮挡的管子。
- 三处动画中再次输入均改为「先跳过，再继续」：`onTap`（点按）、`doUndo`（撤销）、`btnHint`（提示）。

## 四、工程：验证桩常驻化
原 Node 验证桩写在 `/tmp`，每轮被系统清理。本轮落盘为 **`.workbuddy/tools/verify.js`**（`.workbuddy/` 已被 `.gitignore` 排除，不污染仓库）。三个关键改进：
1. **`vm.createContext` 独立上下文**：原先同一 realm 反复 `runInThisContext`，顶层 `const CAP` 二次声明直接 `SyntaxError`。
2. **假 `requestAnimationFrame` 必须递增时间戳**：`animStep` 里 `anim.t += ts - anim.last`，若每帧都传同一个 `16.7`，`t` 恒为 0 → 动画永远跑不完（drain 空转 200 次）。这是本轮踩到的坑。
3. **假 `setTimeout` 走队列 + `drain()`**：`startLevel()` 是 `setTimeout(…,0)` 异步生成，不同步 drain 拿不到关卡。
