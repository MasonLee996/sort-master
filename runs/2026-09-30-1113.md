# 2026-09-30-1113 运行总结（第 90 轮）

**本轮目标**：修复用户反馈——类似签到/死局/说明这类弹窗应是「最上层盖住下面按钮」，而非只盖画布区。

**问题根因**
- 所有 `.overlay`（win/dead/help/sign/ad/gen）原本 `position:absolute`，其父级是 `#stage`（`position:relative; overflow:hidden`），所以 `inset:0` 只覆盖 stage 区域；header 与 footer（撤销/提示/重开/+5步/广告/去广告卡/音效）在 stage 之外，弹窗期间仍可被点，存在误触（如死局时还能点 +5步、签到时还能点广告）。

**修复**
- `index.html` 仅改 CSS：`.overlay{position:absolute;...z-index:20}` → `.overlay{position:fixed;inset:0;...z-index:50}`。
- `fixed` 相对视口，脱离 `#stage` 裁剪；`z-index:50` 高于 toast(30) 与所有静态 header/footer，弹窗期间全屏（含底部按钮）被遮罩盖住且不可点；弹窗内按钮（撤销/加管/重开/领取/下一关等）仍正常可点。
- 一处改动覆盖全部弹窗（均用 `.overlay` 类），无 JS 逻辑变更。

**验证结果**
- A. 语法：`node --check` 抽取脚本 → SYNTAX_OK（JS 未改）。
- B. 渲染回归（异步版）：三档尺寸(500×600 / 500×160 / 340×640)全 RENDER_OK，tubeRects=4、arcs=16、在界内、提示行未被压住；签到逻辑单测 5 例仍全 OK；`addTube` 后 tubeRects=5 仍在界内。CSS 改动不影响 canvas 绘制与通关流程。
- 交互：弹窗模态成立，footer 不再可误触；通关流程（弹窗内按钮）正常。

**四约束核对**：单指点选✅、渐进式✅、广告/内购钩子保留✅、未引入数值售卖✅；零外部资源、单文件可运行、localStorage try/catch✅。
