## 二、这一轮怎么通关的

上一轮卡在 `Setup Pages` 步骤失败。本轮的关键发现：

1. **用户改 Source 后 `has_pages` 由 `false` 变 `true`** —— 这是判断"Pages 是否已开启"的最可靠信号。而 `GET /repos/.../pages` 在首次构建前一直返回 404，**不能拿它当判断依据**（容易误判成"没保存"）。
2. **不用让用户点「Re-run failed jobs」**：往 `main` 推一个真提交同样能触发 workflow。正好 README 缺部署说明，就顺手补上（`ba9e740`）—— 既修了文档又触发了部署，比推一个 `chore: trigger` 的空提交体面。
3. **别点 Pages 页面上的「Configure」模板卡**：那会额外生成一个官方 workflow（`static.yml`/`jekyll-gh-pages.yml`），和仓库里的 `pages.yml` 重复部署、互相抢 concurrency。

## 三、分享链路的线上衔接

`shareUrl()` 的实现决定了这一步会自动正确：

```js
function shareUrl(){
  try{ if(/^https?:/.test(location.protocol)) return location.href.split("#")[0].split("?")[0]; }catch(e){}
  return GH_PAGES_URL;   // file:// / 本地预览时回落
}
```

线上页面 `location.href` 就是 `https://masonlee996.github.io/sort-master/`，所以：
- **复制链接** → 复制到的就是真实可分享地址（无需改代码）
- **生成海报** → 海报里的链接框也是这个地址
- 回落常量 `GH_PAGES_URL` 与真实地址**完全一致**，`file://` 打开时同样正确
