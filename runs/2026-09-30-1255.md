# 第 98 轮 · 提示高亮目标管（P0）

## 做了什么

上一轮刚把「提示给错步」的既有 Bug 修掉（`solve()` 只记根节点首步），这一轮把它**配套收口**：光给对首步还不够——`flashHint` 原先只把**源管**设为选中态，目标管完全没有视觉标记，玩家得从文案「建议：点左侧高亮管 → 目标管」里自己猜"往哪倒"。

### 1. 新增 `hintTarget` 状态 + 目标管渲染

在 `selected`（源管）之外新增 `let hintTarget = -1;`（建议倒入的目标管索引）。`drawTube` 末尾追加目标管高亮：

- **琥珀色虚线呼吸框**：`setLineDash([7,5])` + `roundRect(r.x-5, r.y-5, r.w+10, r.h+10, 16)`，alpha 由 `pulseAlpha()` 驱动（0.55→0.95），与源管蓝色光晕同步呼吸。
- **管口下指箭头**：在 `r.y-10` 画一个朝下的三角，明确"往这里倒"（管子顶部是开口，箭头在外侧不会压住球）。
- 整个块用 `ctx.save()/restore()` 包住，避免 `setLineDash` 状态泄漏给后续绘制。

配色刻意区分：**源管 = 蓝（既有）**，**目标管 = 琥珀 `rgba(255,138,0,…)`**，两框同时出现也一眼分得开。

### 2. 文案与时长

- toast 改「建议：蓝框管 → 琥珀框管」（从"猜"变成"看图"）。
- 高亮时长 600ms → **1200ms**：600ms 对于要看两个框并完成两次点选偏紧。

### 3. 三个必须一起改的配套（不然会留隐患）

| 隐患 | 处理 |
|---|---|
| `pulseTick` 原先 `if(selected<0){ pulseOn=false; return; }` —— 只在有选中态时脉动 | 改为 `if(selected<0 && hintTarget<0)` 才停。**否则提示态没有选中态支撑，呼吸光会立刻停掉**；同时"两者都消失才停 rAF"，不会因为提示拖着一个永不停的 rAF 持续耗电 |
| 玩家在提示高亮期间自己点选，1.2s 后的超时回调会把他的选中态清掉 | 超时回调加条件：`if(selected===pair[0]) selected=-1;` —— 只在玩家**没自己改选**时才复位 |
| 切关 / 加管后 `tubeRects` 重排，旧的 `hintTarget` 会指向错位的管子；旧 `flashHint` 定时器还会在新关卡里触发 | 新增统一出口 `clearHint(quiet)`：`clearTimeout(clearHint._t)` + 清 `hintTarget`/`hintPair`；`quiet=true` 时不 `render()`，专供 `startLevel`/`startDaily`/`addTube` 这类"马上要重排 layout"的场合，避免用旧 `tubeRects` 多画一帧 |

接入点：`onTap`（玩家一操作即退场）、`doUndo`、`startLevel`（quiet）、`startDaily`（quiet）、`addTube`（quiet）。

## 验证数据

```
SYNTAX_OK
--- RENDER ---  500x600 / 500x160 / 340x640 全 OK
--- HINT HIGHLIGHT ---
  arcTo: base=0 仅目标=4 仅源管=4 两者=8
  340x640 tubes=11 框左=81 框右=259 (W=340) 箭头顶=5
=== RESULT: PASS=88 FAIL=0 ===
```
连跑 **8 次**（每次关卡随机重新生成）全部 **PASS=88 / FAIL=0**。

### 这轮测试比上轮更"硬"的两处

1. **不只断言"没抛异常"，而是证明"框真的画了"**：给 ctx 桩的 `arcTo` 加计数。`roundRect` 每个圆角框恰好 4 次 `arcTo`，于是：
   - base（都不高亮）= 0
   - 仅 `hintTarget` = 4 ← **目标管框确实绘制**
   - 仅 `selected` = 4
   - 两者都设 = 8
   把这四个数打出来，比"render 没报错"有说服力得多（既能抓"忘了画"，也能抓"画了两遍"）。
2. **边界用极窄屏 + 最多管数实测**：340×640 + 11 管这一最紧的组合下，断言虚线框左右沿与箭头顶沿都在画布内（实测 框左 81 / 框右 259 / W=340 / 箭头顶 5px）。提示框是**向外扩 5px** 的，这种外扩最容易被窄屏裁掉。

### 验证桩的一处真实缺陷（顺手修）

假 `setTimeout`/`clearTimeout` 之前是"push 到数组 + `clearTimeout` 空实现"，**`clearTimeout` 完全失效**。游戏里 `toast` 用 `clearTimeout(toast._t)`、本轮提示态也用 `clearTimeout(clearHint._t)` —— 空实现会让"取消"类逻辑静默失效，测试**假通过**。已改成 `Map(id→fn)` + 真实 `clearTimeout`/`cancelAnimationFrame`（`drain()` 同步改为遍历 Map）。新增 `step(n)` 用于只想推进有限轮次的场合（提示态带无限脉动 rAF，全 `drain` 不划算）。
