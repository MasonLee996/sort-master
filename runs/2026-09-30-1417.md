## 一、Bug A（严重）：撤销会吞掉「看广告加管」换来的空管

### 现象与复现
撤销栈 `history` 只在普通移动时 `pushHistory()`，**`addTube()` 不入栈**；而 `doUndo()` 是裸的 `tubes = history.pop()`。于是：

```
死局 → 看广告加管（管数 +1）→ 还是过不去 → 点撤销
   → 管数回退到加管之前，付费空管消失
   → 但 addedTubes 仍是 1、HUD 仍显示「加管 1/3」
   → 3 次加管上限实际只剩 2 次可用（白扣一次）
```

这条正是**死局出口的预期使用路径**，不是角落场景。上轮刚花了整轮保证"不能看完广告却什么也没拿到"，这个 Bug 把那件事从另一个方向破掉了。

### 先证明再修
新增探针 `.workbuddy/tools/probe_undo_tube.js`（复用 `verify.js` 的 DOM 桩，见第四节）。修复前输出：

```
初始管数 base = 4  addedTubes = 0
落一步 [0,1]        管数 = 4  history = 1
addTube() -> true   管数 = 5  addedTubes = 1
doUndo() 后         管数 = 4  addedTubes = 1   期望管数 = base+addedTubes = 5
BUG_CONFIRMED
```

> 顺带一个坑：探针第一版写成「加管 → 倒球 → 撤销」，结果**测不出来**（`pushHistory` 在加管之后，历史里已含 5 管）。必须按真实路径「先倒球 → 再加管 → 再撤销」才复现。

### 修法
新增 `baseTubes`（生成时的管数，`startLevel` / `startDaily` 的 build 里记录）。`doUndo()` 回填后补齐：

```js
const want = baseTubes + addedTubes;
while(tubes.length < want) tubes.push([]);   // 与 addTube 的追加位置一致
```

补回的必然是**空管**：撤销跨过加管点时，那次加管本来就是空的，之后倒进它的球属于更晚的移动、已被撤销。修复后探针输出 `管数 = 5` → `OK`。

## 二、Bug B：`randomFill` 会静默丢球 → 畸形关卡

旧实现给每颗球「随机试 50 次找未满管」，50 次全落空就**直接丢掉这颗球**（`let bi` 是没写完的守卫：只自增、从不读，是这段代码没写完的证据）。

后果链：某色只剩 `CAP-1` 颗 → 而 `isWin` 判「整管同色」**不要求管满** → 出现"3 颗同色也算通关"的题面，且总球数不再等于 `colors*CAP`。

修法：维护 `free`（未满管索引）列表，等概率取管、放满即从列表移除：

```js
const free = []; for(let t=0;t<total;t++) free.push(t);
for(const b of balls){
  const k = (rnd()*free.length)|0;
  const t = free[k];
  s[t].push(b);
  if(s[t].length >= CAP){ free[k] = free[free.length-1]; free.pop(); }
}
```

顺带把拒绝采样的空转也省掉了，且**保持确定性**（`rnd` 消费顺序确定，每日题面仍全服一致）。

## 三、Bug C：「一开局就已排好」的废题（新号前两关命中率约 3%）

### 发现过程（偶然）
`verify.js` 的 `SOLVE 1..20` 段某次跑出：

```
提示首步非法: 2 -> null
```

`found` 为 `null` 而 `solvable` 为真 → 说明 `solve()` 返回了 `{first:null}`。机制：`dfs` 在 `depth 0` **先判 `isWin(s)`**，若初始态已满足「每管空或单色」就直接 `return true`，而 `bestFirst` 只在进入循环后才赋值 → 保持 `null`。

### 玩家可见后果
- `win()` 只经 `afterMove()` 触发（**只在移动之后判定**）→ 玩家盯着已经摆好的盘面，**永远等不到通关结算**；只能自己把球打乱重排。
- 提示按钮只吐「无可用提示」（`if(r && r.first)` 不成立）。
- 每日谜题若命中，**全服一整天都是废题**（种子确定性）。

### 量化（`probe_presolved.js`，20000 采样/组）
| 颜色数 | 空管1 | 空管2 | 空管3 |
|---|---|---|---|
| 2 | 2.125% | **3.265%** | 4.555% |
| 3 | 0.010% | 0.010% | 0.035% |
| 4 / 5 / 6 / 8 / 10 | 0.000% | 0.000% | 0.000% |

`genLevel(1)` 与 `genLevel(2)` 都是 **2 色 + 2 空管** → **每个新号前两关各有 ~3% 概率踩雷**。这也是本轮一开始那条"提示首步非法"失败的唯一来源。

### 修法
```js
if(isWin(cand)) continue;   // 必须「还没排好」才算合格题面
if(solve(cand)){ s = cand; break; }
```
兜底分支同步改为「从已排好退一步」：构造已完成态后把首管顶球挪到最后一根空管 → 既非已完成，又必定 1 步可解。

## 五、⚠️ 方法论教训（重要）

上轮结束时写的是「**PASS=160/FAIL=0 连跑 8 次全绿**」——**但那是运气**。Bug C 在 2 色关卡上约 3% 命中、每整轮跑约 6% 概率失败，8 次连跑不失败的概率只有约 61%。也就是说：

> **对"概率性不变量"，连跑 N 次全绿不构成证据。**必须像 `probe_presolved.js` 那样做**固定 N=20000 的显式采样**把概率量出来，再用**大样本断言**（200 次生成）把它钉住，而不是靠重复跑。上轮的断言写对了（所以这轮它真的抓到了 Bug），但"稳定绿"这个结论下得太早。

工具链改进：新增的探针脚本用「切 `verify.js` 断言段之前的部分 + 包一层 `new Function` 导出 `makeEnv`/`boot`」的方式复用 DOM 桩，**不必改 `verify.js` 结构、也不重复写 200 行的 DOM stub**：

```js
const head = src.slice(0, src.indexOf("/* ---------------- 断言 ---------------- */"));
new Function("module","exports","require","__dirname", head + "\nmodule.exports={makeEnv,boot};")(...)
```

这个模式后续写任何一次性探针都能直接用。
